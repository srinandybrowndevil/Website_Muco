# Station 1 — R&D Brief
## Website Preview experience (Frontend V1) · Loop 1

**Product type:** Website (feature inside the existing marketing site).
**Done means:** Implemented in this repository, running, verified in a browser.
**Source of truth:** `MUCO_Website_Preview_Frontend_V1_Claude_Code_Master_Prompt.md`.

---

## 1. The problem being solved

A local business owner deciding whether to commission a website is asked to make a
purchase decision about something they cannot see. Every competing studio asks the
same of them. The enquiry form is therefore filled in by people who already knew
they wanted a website, and by almost nobody else.

The Website Preview inverts that: the visitor enters five facts about their business
and immediately sees their own business name, services and town rendered inside five
genuinely different website designs. The product principle, taken from the brief and
adopted without modification:

> Do not ask the customer to imagine a website. Show them one.

## 2. What this phase is, precisely

A **frontend visual prototype tool**. It is not a website builder and it publishes
nothing. Nothing is sent to a server. No AI is involved. Every word on every
generated preview is derived deterministically from what the visitor typed plus a
template configuration.

Naming this correctly matters commercially as well as technically. The honesty
position this site already carries — "we do not publish testimonials, client logos
or metrics we cannot verify" — breaks the moment this tool claims to be
AI-generated, calls the preview a real website, or fakes a submission to MUCO LABS.
The copy rules in section 9 are therefore a hard constraint, not a preference.

## 3. Constraints discovered in the existing repository

Read out of the code, not assumed.

| Constraint | Source | Consequence for this feature |
|---|---|---|
| Pages are generated by Python and committed; never hand-edit `.html` | `HANDBOOK.md`, `build.py` | The new page is a builder function registered in `content.build_all()` |
| `script-src 'self'` — no inline script, no CDN | `build_vercel_json()` in `content.py` | App code ships as one same-origin file. No third-party library |
| `style-src 'self' 'unsafe-inline'` | same | An injected `style` element inside a shadow root is permitted |
| `img-src 'self' data:` — **`blob:` is absent** | same | `URL.createObjectURL()` for an uploaded logo would be blocked by the browser. Uploads must be read as `data:` URLs through `FileReader` |
| `font-src 'self'` | same | Only the three self-hosted families are usable: Inter Tight, Instrument Serif, JetBrains Mono. No Google Fonts |
| `frame-src 'self'` | same | An `iframe srcdoc` preview risks being blocked. Rejected in favour of shadow DOM |
| `render()` runs two regex post-processors over every page body (`rule_labels`, `band_sections`) | `build.py:276`, `:300` | Preview markup must be produced at runtime by JavaScript, never as static body markup, or the post-processors rewrite it |
| `scripts/build-site.mjs` copies an explicit file list into `public-site/` | that file | A new JavaScript file missing from that list builds locally and 404s in production |
| `scripts/site-audit.py` fails the build on duplicate titles, missing descriptions, heading-level skips, missing `alt`, more than one `h1`, duplicate `id` | that file | The new page must satisfy all of these at build time |
| The site is single-theme dark, one copper accent | `style.css:122` | The five generated business websites need their own colour systems. Global CSS must not reach them, and their CSS must not reach the site |

## 4. The decisive technical question

Five concepts must render as *real websites*, several of them light-background, each
with its own type scale, spacing system and palette — inside a dark studio interface
whose global stylesheet already styles `h1`, `p`, `a`, `section` and `.btn`. Three
isolation strategies exist:

1. **`iframe srcdoc`** — perfect isolation and true media queries, but `frame-src
   'self'` makes `about:srcdoc` a deployment risk, and every frame becomes a
   separate document to keep accessible and in sync.
2. **Prefixed class names** — not isolation. Inherited properties and any element
   selector in a 140 KB stylesheet still land on the preview.
3. **Shadow DOM plus CSS container queries** — chosen.

Shadow DOM gives absolute style isolation in both directions with no build step. The
consequence is that `@media` no longer describes the preview, because a media query
inside a shadow root still measures the browser window. That is solved rather than
worked around: the preview host declares `container-type: inline-size`, and every
breakpoint in all five templates is written as `@container`. Changing the device
frame from 1280px to 390px therefore makes the generated website's own breakpoints
fire, which is what brief section 17 demands and what a CSS `transform` scale would
only have simulated.

Fonts registered by `@font-face` in the document stylesheet stay usable inside a
shadow root, so the three self-hosted families are available to the templates.

## 5. Differentiation strategy (brief section 12, the stated failure condition)

Five recoloured layouts is a failure. Differentiation is therefore specified at the
level of structure. Each template owns its own header composition, hero composition,
section rhythm, card treatment, alignment, radius, border weight and type scale:

| # | Family | Header | Hero | Cards | Radius | Density |
|---|---|---|---|---|---|---|
| 1 | Minimalist | Centred wordmark, nav beneath, hairline | Centred, narrow measure, text-link CTA | None — hairline rows | 0 | Very low |
| 2 | Maximalist | Solid colour bar, bold caps nav, pill CTA | Full-bleed colour, oversized headline, marquee | Hard-offset shadow blocks | 0–4px | Very high |
| 3 | Modern Business | Sticky white, phone number, button right | Two-column, offer card beside copy | Soft-shadow white cards, icon tiles | 14px | Medium |
| 4 | Geometric Editorial | Asymmetric 12-column, visible grid rules | 7/5 split, oversized numeral, mono captions | Bordered modules of unequal span | 0 | Medium-high |
| 5 | Premium | Transparent over dark, centred letterspaced serif | Full-height dark, light serif, outline CTA | Full-width image panels, hairline rules | 2px | Low, grand scale |

The acceptance test stands as written: in greyscale these must still read as five
different websites.

## 6. Typography, honestly bounded

The brief asks for five curated type sets. `font-src 'self'` permits three families.
A sixth loaded from a CDN would be blocked by the browser, and shipping more woff2
files is outside a frontend phase. Five distinct typographic voices are therefore
composed from three self-hosted families plus system stacks, differentiated by
family, weight, case, tracking and scale:

| Set | Headings | Body |
|---|---|---|
| Clean Sans | Inter Tight 600, tight tracking | Inter Tight 400 |
| Modern Grotesk | system-ui 700, uppercase, wide tracking | system-ui 400 |
| Elegant Serif | Instrument Serif 400 | Inter Tight 400 |
| Bold Display | Inter Tight 800, very tight tracking | Inter Tight 400 |
| Technical Mono | JetBrains Mono 600, uppercase, wide tracking | Inter Tight 400 |

Recorded as a deliberate limitation in the final report rather than hidden.

## 7. Category model

Fourteen categories are required. Each carries more than a label: a default section
set, call-to-action wording, the noun for what it sells (dishes, services, projects,
treatments), a placeholder-imagery motif, and headline patterns. A Premium Bakery
and a Premium Construction Company must differ in more than their text, which is the
requirement of brief section 33.

Placeholder imagery is generated — a CSS gradient plus an inline SVG motif per
category. No stock photography. A stock photograph on a preview implies it is a
photograph of the visitor's business, which section 40 forbids and which this
studio's honesty position forbids independently. It also keeps page weight at zero.

## 8. Data model — the separation brief section 19 calls critical

Three independent records, persisted separately:

- `BusinessDraft` — everything the visitor typed. Never touched by a template change.
- `TemplateSelection` — which of the five is active.
- `WebsiteCustomization` — presentation only, **keyed by template id**, so switching
  to Design 4 and back to Design 1 restores Design 1's customisation rather than
  carrying Design 4's palette into it.

Persistence goes through one `PreviewRepository` interface with a single local
implementation, so a future Supabase implementation replaces one object.

## 9. Copy rules (hard constraints)

Forbidden anywhere in the feature or in any generated preview:

- "AI-generated", "instantly generated", "ready to publish", "your new website"
- Invented years in business, customer counts, ratings, awards, certifications,
  prices, staff names, project counts, or attributed testimonials
- Any claim that data was sent to MUCO LABS, saved, or emailed
- Any image or caption implying "our team", "our branch", "our customers"

A testimonial-shaped section is permitted only when visibly labelled as a layout
example carrying unattributed placeholder content.

## 10. Organic acquisition (digital growth gate)

`/website-preview` is a genuine search target, not an app shell. It ships with a
real `h1`, a written explanation of the process, an FAQ with `FAQPage` schema, a
`Service` entity, breadcrumbs, a canonical and a sitemap entry at priority 0.9.
Primary intents served: *see what my business website could look like*, *website
design ideas for a shop in Erode*, *free website mockup*. The interactive studio
mounts into the page without removing that content from the document.

Entry points, per brief section 4: primary navigation, homepage hero, a dedicated
homepage section, the website development service page, the pricing page, the footer.

## 11. Assumptions

- **A.** Visitors will not expect the preview to be a purchasable website. Mitigated
  by copy, not by hope. Confidence: medium.
- **B.** Container-query support is acceptable for this audience (Chrome 105+,
  Safari 16+, Firefox 110+, all shipped 2022–2023). Browsers without it render the
  preview at desktop composition. Confidence: high.
- **C.** Five templates is the right number to show without fatigue. Taken from the
  brief; not independently validated.

## 12. Out of scope, confirmed

Backend, database, Supabase, lead persistence, email, WhatsApp automation, CRM,
admin, auth, any Google API, any AI API, payments, domains, server uploads, share
links, deployment, CMS. Nothing in this phase may create an extension point that
already talks to one of these.

# Professional English report standard

All artifacts are professional English. No Tanglish. No slang. No emoji in headings.

## Master report sections (00-MASTER-REPORT.md)

1. Title, product type, loop number, date, classification (website / e-commerce / app / software)
2. Executive summary — one page, non-technical, honest
3. Objective and intake (idea or prompt restated)
4. Scope, environments, tools, limits
5. Method — stations run, stations skipped and why
6. R&D synopsis — users, rules, intent map
7. Design synopsis — IA, critical screens, placeholder policy
8. Frontend synopsis — routes, states, client risks
9. Backend synopsis — contracts, data, integrity risks
10. Test synopsis — cases planned, run, blocked
11. QA findings table — ID, title, severity, layer, owner role, fixable, effort
12. Finding deep-dives — fields A through J
13. Growth and organic-lead assessment — SEO, AEO, AIO, GEO, SEM/SMM/SSCM as applicable
14. Certification result — pass / fail / pass with S3–S4 punch list
15. Loop-back instructions for R&D if failed
16. Quick wins (this week) and structural work (this month)
17. Open questions and assumption log

## Station reports

Use the same voice. Start with purpose, inputs, outputs, risks, and a handoff checklist for the next station.

## Tone

- Precise nouns. Short sentences. Active voice.
- After a technical term, one plain English clause.
- No flattery. Evidence, then the path up.
- Severity is not a sales adjective.
